# 账号采购与使用成本

在配置文件设置 `"costTrackingEnabled": true` 后启动服务，登录管理后台打开「账号成本」。凭据卡片的「查看账号成本」可直达该账号。管理端使用原有 Admin API 密钥。

- 按凭据录入每笔采购的 CNY 实付金额、实际可用积分、付款、生效和到期时间。续费和加购新增批次。已预付的历史剩余额度用「期初余额」录入剩余积分及其成本，报表期间现金支付不重复统计。
- 使用成本按每次出站调用的积分报告分摊。套餐优先，加购最后，同类优先消耗较早到期的批次。每笔批次金额分摊保留 8 位小数，尾差在用完时合拢。
- 到期的本地批次停止分摊。确认上游权益到期后，可将该批次未用部分确认为损失。支出、使用、剩余及损失各有独立口径。
- 选择今天、本月或近几天查看整体成本，点击凭据 ID 查看采购批次及近 100 条出站尝试。报表可导出 JSON。日期筛选采用浏览器本地时区，接口接受 RFC3339 的 `from`、`to`（左闭右开）。

采集从启用时开始，原始计量数字存入与凭据文件同目录的 `costs.db`。报表按调用时间计算，如果补录的批次生效于过去，重新查询该期间会按新增批次分摊先前用量。保留凭据数据目录和一致的 SQLite 备份，运行中请使用 SQLite backup API。多套独立凭据应使用不同数据目录。使用管理端新增和删除凭据，更换实际账号需新增凭据。删除凭据后历史可按原 ID 查询。

余额快照使用已有刷新结果，供人工对账参考。缺失或部分计量、没有采购单覆盖的积分、独立 MCP 计量不可用均单列。账本写入异常时采集质量可能下降。历史覆盖、上游实际扣账和外部客户端用量需结合余额或账单判断。当前记录已知预付成本与到期损失，超额费用、退款及共享池需要单独对账。

管理操作及报表接口位于 `/api/admin/costs`。报表的货币和积分数值以十进制字符串返回。采购写入用请求体 `id`（UUID）实现幂等，相同请求重试应使用相同 ID。
